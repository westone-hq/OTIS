# TUNE Summary Report — 레이아웃 확정용 프로토타입

OTIS TUNE 리포트를 템플릿 이미지 위에 재구성하는 파이썬 프로토타입.
**목적은 산출물 자체가 아니라 좌표표(`layout.json`)를 확정하는 것**이다.
확정된 좌표는 Flutter 앱(Dart)으로 옮긴다.

## 실행

```bash
pip install reportlab matplotlib numpy pypdf openpyxl pillow

python build_sample.py --source evimp --out out/sample_evimp.pdf
python build_sample.py --source xlsx  --out out/sample_app.pdf
python build_sample.py --source evimp --out out/debug.pdf --debug
```

`--debug` 는 모든 플레이스홀더에 마젠타 십자와 키 이름을 찍는다. 좌표가 틀어졌는지
눈으로 바로 확인할 수 있다. 차트 영역은 사각형으로 표시된다.

`--original-axes` 는 진동 축을 원본 범위(±4 / ±10)로 되돌린다. 필터 확정 후 사용.

## 구조

```
layout.json          좌표표. 이 파일 하나가 이 프로젝트의 산출물이다.
tune_report/
  metrics.py         측정 데이터 -> 지표 + 판정. 렌더링을 전혀 모른다.
  charts.py          matplotlib 차트를 A4 투명 PDF로. 축 범위 상수 포함.
  render.py          배경 + 플레이스홀더 + 차트 합성.
build_sample.py      데이터 로더와 CLI.
assets/              템플릿 이미지, 한글 폰트.
```

`metrics.py` 와 `render.py` 는 `ReportMetrics` 객체로만 연결된다. 필터가 확정되면
`metrics.compute()` 안쪽만 고치면 되고 렌더링은 건드릴 일이 없다.

## 판정 기준

`Vibration_Checking_App_Development_20260630.pdf` 6쪽이 정본이다.

| 구분 | 적색 기준 |
|---|---|
| X축 진동 p2p | 10 mg 초과 |
| Y축 진동 p2p | 10 mg 초과 |
| Z축 진동 p2p | 15 mg 초과 |
| 소음 최대 | 50 dBA 초과 |
| 운행 거리 · 최대 속도 | 기준 없음 |

요구사항에 황색 단계가 없으므로 **템플릿의 황색 컬럼은 비운다.** H6N1AP65 의
2단계 값(57/60, 72/75, 14/21 …)은 기존 iOS TuneApp 기준이라 쓰지 않는다.

헤더는 요구사항서 '현장 정보'를 우선 배치하고, 앱에 없는 칸은 고정값 또는 공백이다.
제번 → 측정 ID, 현장명 → 건물명, 최하층·최상층 → 층 정보. 제품 `엘리베이터`,
품질성능기준 `Standard`, 측정 `층간 시험` 은 고정. 하중과 주소는 공백.

## 좌표 체계

모든 좌표는 **템플릿 이미지 픽셀(2256 × 3190, 좌상단 원점)** 기준이다.
템플릿은 정확히 A4 비율이라 변환이 단순하다.

```
x_pt = x_px * 0.263863475      (595.276 / 2256)
y_pt = 841.89 - y_px * 0.263915361   (841.89 / 3190)
```

원본 리포트 페이지 이미지(924 × 1316)에서 측정한 값은 K = 2.44156 을 곱해 변환했다.
원본 이미지는 A4보다 세로로 9px 남는 여백이 있을 뿐 배율은 x·y 동일하다(푸터 위치로 검증).

### 확정된 주요 좌표

| 요소 | x | 정렬 |
|---|---|---|
| 신호등 원 | 중심 243, 지름 30 | — |
| 카테고리 | 313 | 좌 |
| 설명 라벨(템플릿에 박힘) | 741 → 1004 | 좌 |
| **측정값 (1~6행)** | **1016** | 좌 |
| **측정값 (7~8행)** | **742** | 좌 |
| 황색 컬럼 | 1531 | 비움 |
| 적색 임계값 | 1855 | 중앙 |

Performance Metrics 행 y(텍스트 수직 중심):
`995 / 1101 / 1210 / 1320 / 1429 / 1538 / 1648 / 1743`
**행 간격이 일정하지 않다: 106 109 110 109 109 110 95.** 마지막 한 칸만 95 로 크게 좁고 첫 칸도 106 으로 약간 좁다. 균등 피치(평균 106.9)로 넘겨짚으면 8행이 12픽셀 밀린다. 계산하지 말고 값을 그대로 박을 것.

분석 자료 행 y: `2098 / 2199 / 2300 / 2401 / 2504 / 2606 / 2707`, 설명 컬럼 x = 1172.

차트 슬롯(축 프레임 기준): x 283, w 1458, h 198, y = `415 / 896 / 1377 / 1858`.

## 구현하면서 확인한 것

- **최대 속도·운행 거리 행에는 원본에도 신호등 원이 없다.** 요구사항에도 기준이 없다.
- **템플릿에 적색 컬럼 전체와 마지막 두 행의 황색 `0` 이 남아 있다.** 줄무늬
  색(`#E6E9EE` / `#FAF6ED`)으로 덮고, 적색만 기준이 있는 행에 다시 찍는다.
  1행 신호등 자리에도 지워지다 만 원이 흐리게 남아 있어 같이 덮는다.
- **소음 최대는 원시 전체 최대를 쓴다.** 원본 리포트는 48.7 dBA, 원시 최대는
  65.6 dBA 로 다르지만, `진행상황_및_향후일정.docx` 가 측정 중 충격은 실제 거동으로
  포함하고 시작·종료 조작에서 오는 값은 측정 절차 안내로 배제한다고 정하고 있다.
  계산으로 구간을 빼지 않는다.
- **소음 차트는 원시 데이터로 원본과 거의 일치한다.** 축 40–54 고정, 위아래 잘림까지
  원본과 같다. 골과 스파이크 위치가 그대로 재현된다.
- **파생 물리량 검증**: 원본 리포트의 최대 속도 1.75 m/s · 운행 거리 57.3 m 에 대해
  이 코드는 1.7 m/s · 57.1 m 를 낸다. 적분 경로가 맞다는 뜻이다.

## 남은 것

1. **진동 필터** — X/Y/Z 진동 지표는 `None` 이라 리포트에 `—` 로 나오고 판정은
   회색이다. 필터 확정 후 `metrics.compute()` 의 해당 항목만 채우면 된다.
   수평 행에는 X·Y 중 큰 값을 싣고 어느 축이었는지를 `detail` 에 함께 적는다 —
   요구사항이 X 와 Y 를 각각 보고하도록 정하고 있다.
2. **진동 차트 축** — 원본은 X ±4 / Y ±10 인데 이건 필터 통과 후 기준이다. 원시를
   그대로 그리면 8% 이상 잘리므로 임시로 ±10 / ±15 로 넓혀 두었다.
   `charts.use_original_vibration_limits()` 로 되돌린다.
3. **jerk 차트** — 원시 가속도를 그대로 미분해 고주파 잡음이 남는다. 원본은 저역통과
   후 미분한 매끈한 곡선이다. 필터와 함께 정리한다.
필터 관련 세 가지가 전부다. 아래 두 항목은 확정됐다.

- **분석 자료 7개 항목** — 회색(미확정) 유지. 요구사항에 없고 판정 근거도 없다.
  녹색으로 바꾸지 마라.
- **엔지니어명** — 공백 유지. 로그인 ID 를 끌어오지 않는다.

## Dart 이식 시 주의

- **matplotlib 은 앱에서 못 쓴다.** 이 프로토타입은 좌표와 스타일을 확정하기 위한
  것이고, 앱에서는 `pdf` 패키지 캔버스에 폴리라인으로 직접 그리거나 위젯을 캡처해야
  한다. `pubspec.yaml` 에 `pdf` 패키지가 아직 없다.
- 여기서 나온 `sample_evimp.pdf` 를 **정답 이미지**로 두고 Dart 결과물과 픽셀 비교하면
  이식이 맞게 됐는지 검증할 수 있다.
- `layout.json` 은 그대로 Dart 에서 읽을 수 있다. 좌표 변환식만 옮기면 된다.
- 폰트는 NanumGothic 을 썼다. 원본 폰트가 아니라 자간이 조금 다르다. 앱에서 쓰는
  폰트로 바꾸고 설명 컬럼의 라벨–값 간격만 다시 확인하면 된다.
- 배경 이미지는 273 DPI JPEG 이고 3페이지 합쳐 약 1 MB 다. 메일 첨부로는 문제없지만
  더 줄이려면 200 DPI 로 다시 뽑으면 된다.

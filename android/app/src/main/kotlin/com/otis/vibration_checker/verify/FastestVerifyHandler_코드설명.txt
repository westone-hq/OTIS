===============================================================================
FastestVerifyHandler.kt 전체 코드 설명
===============================================================================

대상 코드:
FastestVerifyHandler.kt

목적:
1. Android 센서에서 raw / gravity / linear 값을 최대한 빠르게 받는다.
2. 실제로 받은 원본과 수신 간격을 기록한다.
3. 불규칙한 원본 사이를 선형 보간해서 정확한 256Hz 시간축을 만든다.
4. 측정이 끝나면 원본과 256Hz 결과를 3~7.txt 하나로 합친다.


===============================================================================
0. 전체 흐름
===============================================================================

Flutter 검증 시작 버튼
    ↓
start(256)
    ↓
registerListener(..., SENSOR_DELAY_FASTEST)
    ↓
Android가 센서 이벤트를 줄 때마다 onSensorChanged() 실행
    ↓
원본값 임시 txt에 기록
    ↓
linear 센서 시각을 기준으로 3.90625ms마다 선형 보간
    ↓
256Hz 결과를 다른 임시 txt에 기록
    ↓
stop()
    ↓
통계 + 원본 + 256Hz 결과를 하나로 합침
    ↓
Flutter가 이 파일을 3~7.txt로 저장

3. AxisSample: 보간에 필요한 이전점·현재점 (35~69행)
===============================================================================

private data class AxisSample(
    var prevTs: Long = 0L,
    var prevX: Float = 0f,
    var prevY: Float = 0f,
    var prevZ: Float = 0f,
    var currTs: Long = 0L,
    var currX: Float = 0f,
    var currY: Float = 0f,
    var currZ: Float = 0f,
)

각 변수:
- prevTs: 직전에 받은 센서값의 시각(ns)
- prevX/Y/Z: 직전에 받은 X/Y/Z
- currTs: 가장 최근에 받은 센서값의 시각(ns)
- currX/Y/Z: 가장 최근에 받은 X/Y/Z

왜 두 점이 필요한가:
- 선형 보간은 이전점과 현재점을 직선으로 연결한다.
- 그 직선 위에서 원하는 시각의 값을 계산한다.

예:

이전점: 0ms, X=10
현재점: 8ms, X=18
목표점: 4ms

4ms는 0ms와 8ms의 정확한 중간이므로 보간값은 X=14다.

3-1. push() 함수 한 줄씩 설명 (46~56행)
-------------------------------------------------------------------------------

fun push(ts: Long, x: Float, y: Float, z: Float) {

설명:
- 새 센서값 한 개를 AxisSample에 넣는 함수다.
- ts는 센서 시각, x/y/z는 축 값이다.


if (currTs == 0L) {

설명:
- currTs가 0이면 아직 센서값을 한 번도 받은 적이 없다는 뜻이다.
- 첫 번째 센서값에는 이전점이 없으므로 별도 처리한다.


prevTs = ts; currTs = ts

설명:
- 첫 번째 값의 시각을 이전 시각과 현재 시각 양쪽에 모두 넣는다.
- 세미콜론(;)은 한 줄에 명령을 두 개 적었다는 뜻이다.
- 아래와 완전히 같다.

prevTs = ts
currTs = ts


prevX = x; prevY = y; prevZ = z

설명:
- 첫 번째 X/Y/Z를 이전점에 넣는다.


currX = x; currY = y; currZ = z

설명:
- 같은 첫 번째 X/Y/Z를 현재점에도 넣는다.
- 첫 이벤트에서는 이전점과 현재점이 동일하다.


return

설명:
- 첫 번째 값 저장이 끝났으므로 push() 함수를 즉시 종료한다.
- 아래쪽의 "현재점을 이전점으로 이동"하는 코드는 실행하지 않는다.


if (ts <= currTs) return

설명:
- 새로 들어온 시각이 현재 시각보다 과거이거나 같으면 무시한다.
- 시간 순서가 뒤집힌 값을 보간에 넣으면 계산이 잘못될 수 있기 때문이다.


prevTs = currTs; prevX = currX; prevY = currY; prevZ = currZ

설명:
- 지금까지의 현재점을 이전점으로 옮긴다.

변경 전:
prev = A
curr = B

변경 후:
prev = B
curr = 아직 B


currTs = ts; currX = x; currY = y; currZ = z

설명:
- 방금 받은 새 센서값을 현재점에 넣는다.

최종 상태:
prev = 직전에 받은 B
curr = 새로 받은 C

그림:

센서값 B ---------------- 센서값 C
       prev                  curr
             ↑
      이 사이에서 256Hz 목표 시각의 값을 계산한다.

3-2. at() 선형 보간 함수 (58~68행)
-------------------------------------------------------------------------------

fun at(targetTs: Long): Triple<Double, Double, Double>

설명:
- targetTs 시각에서의 X/Y/Z 값을 계산한다.
- Triple은 값 세 개(X, Y, Z)를 묶어서 반환하는 Kotlin 자료형이다.


if (currTs == 0L) return Triple(0.0, 0.0, 0.0)

설명:
- 센서값이 아직 하나도 없으면 계산할 수 없으므로 0, 0, 0을 반환한다.


val delta = currTs - prevTs

설명:
- 이전점과 현재점 사이의 시간 차이를 계산한다.
- 단위는 나노초(ns)다.


if (delta <= 0L) return Triple(currX.toDouble(), ...)

설명:
- 두 점의 시간이 같거나 잘못된 경우 나눗셈을 할 수 없다.
- 이때는 가장 최근값을 그대로 반환한다.


val alpha = ((targetTs - prevTs).toDouble() / delta).coerceIn(0.0, 1.0)

설명:
- alpha는 목표 시각이 두 점 사이에서 어느 위치인지 나타낸다.
- alpha=0: 이전점 위치
- alpha=0.5: 두 점의 중간
- alpha=1: 현재점 위치
- coerceIn(0.0, 1.0)은 결과가 0보다 작거나 1보다 커지지 않게 제한한다.


prevX + alpha * (currX - prevX)

설명:
- X축 선형 보간 공식이다.
- Y와 Z도 같은 방식으로 계산한다.
- 단순 평균이 아니다. 목표 시각의 위치 비율 alpha를 반영한다.

4. Stats: 총개수와 수신 간격 통계 (71~96행)
===============================================================================

Stats는 raw, gravity, linear마다 별도로 하나씩 사용한다.

변수:
- count: 받은 총개수
- lastNs: 같은 센서 타입의 직전 시각
- intervalCount: 정상적으로 계산된 간격 개수
- sumUs: 모든 간격을 더한 값
- minUs: 가장 짧은 간격
- maxUs: 가장 긴 간격


fun add(ts: Long): Long

설명:
- 센서값을 하나 받을 때마다 호출한다.
- 총개수와 간격 통계를 갱신하고 이번 간격 dtUs를 반환한다.


val dtUs =
    if (lastNs > 0L && ts > lastNs) (ts - lastNs) / 1000L
    else 0L

설명:
- 센서 timestamp는 ns 단위다.
- 1000으로 나눠 µs 단위로 바꾼다.
- 첫 값은 직전값이 없으므로 dtUs=0이다.


count++

설명:
- count에 1을 더한다.
- count = count + 1과 같다.


if (dtUs > 0) {
    intervalCount++
    sumUs += dtUs
    minUs = minOf(minUs, dtUs.toDouble())
    maxUs = maxOf(maxUs, dtUs.toDouble())
}

설명:
- 정상 간격만 평균/최소/최대 계산에 넣는다.
- sumUs += dtUs는 sumUs = sumUs + dtUs다.
- minOf는 기존 최소값과 새 간격 중 더 작은 값이다.
- maxOf는 기존 최대값과 새 간격 중 더 큰 값이다.


lastNs = ts

설명:
- 다음 이벤트의 간격을 계산하기 위해 이번 시각을 저장한다.


meanUs = sumUs / intervalCount

설명:
- 평균 수신 간격(µs)이다.


hz = 1,000,000 / meanUs

설명:
- 1초는 1,000,000µs다.
- 평균 간격이 3906.25µs라면 약 256Hz다.


safeMinUs

설명:
- 값이 하나도 없으면 minUs에는 Double.MAX_VALUE가 남아 있다.
- 그 큰 숫자를 출력하지 않고 0으로 바꿔준다.

override fun onSensorChanged(event: SensorEvent?)

설명:
- Android가 센서값을 줄 때마다 자동 호출된다.
- 직접 반복문으로 센서를 읽는 구조가 아니다.


if (!running || event == null) return

설명:

설명:
- 센서 하드웨어 기준 시각이다.
- 단위는 ns이며, 보간과 수신 간격 계산에 사용한다.
- System.currentTimeMillis()보다 센서 간격 계산에 적합하다.


x/y/z = event.values[0/1/2]

설명:
- 센서가 보낸 X/Y/Z축 값이다.
- Android 원래 단위는 m/s²다.


when (event.sensor.type)

설명:
- 이번 이벤트가 raw인지 gravity인지 linear인지 구분한다.


TYPE_ACCELEROMETER

동작:
1. writeOriginal("raw", ...)로 원본 txt와 통계를 기록한다.
2. raw.push(...)로 보간용 이전점/현재점을 갱신한다.
3. return으로 이번 콜백을 끝낸다.


TYPE_GRAVITY

동작:
1. gravity 원본을 기록한다.
2. gravity 보간 버퍼를 갱신한다.
3. return한다.


TYPE_LINEAR_ACCELERATION

동작:
1. linear 원본을 기록한다.
2. return하지 않고 아래 256Hz 생성 로직까지 진행한다.

왜 linear만 아래로 진행하는가:
- 세 센서가 들어올 때마다 256Hz 시계를 돌리면 샘플이 중복 생성된다.
- 따라서 linear timestamp 하나만 대표 시계로 사용한다.
- raw와 gravity는 가장 가까운 이전/현재값을 같은 목표 시각에 보간한다.


if (linear.currTs == 0L)

설명:
- 첫 linear 이벤트에는 직전점이 없어서 보간할 수 없다.
- 첫 점을 저장하고 256Hz 시작 시각만 지정한 뒤 끝낸다.


linear.push(ts, x, y, z)

설명:
- 두 번째 이벤트부터 이전점과 현재점이 만들어진다.


while (nextTargetNs <= ts)

설명:
- 현재 실제 센서 시각까지 만들어야 할 256Hz 목표 시각을 모두 처리한다.

예:
- 이전 실제 콜백: 0ms
- 현재 실제 콜백: 8ms
- 목표 간격: 약 3.906ms

생성 목표:
- 0ms
- 3.906ms
- 7.812ms

다음 목표 11.718ms는 현재 콜백 8ms보다 미래이므로 다음 센서 이벤트까지 기다린다.


linear.at(nextTargetNs)
raw.at(nextTargetNs)
gravity.at(nextTargetNs)

설명:
- 세 센서 모두 동일한 목표 시각에서 값을 계산한다.
- 결과적으로 한 행에 시각이 맞춰진 linear/raw/gravity 값이 들어간다.


.mg()

설명:
- 계산된 m/s² 값을 mg 단위로 변환한다.


writeProcessed(...)

설명:
- 완성된 256Hz 한 행을 processed 임시 파일에 기록한다.


nextTargetNs += targetIntervalNs

설명:
- 다음 목표 시각으로 약 3.906ms 전진한다.
- 이 누적 시각 때문에 최종 결과가 등간격 256Hz가 된다.


if (ts - statsWindowNs >= 1초)

설명:
- 약 1초마다 Flutter 검증 화면에 현재 통계를 보낸다.

===============================================================================
19. 꼭 기억할 핵심
===============================================================================

1. SENSOR_DELAY_FASTEST는 "정확히 3~7ms" 설정이 아니다.
   Android에 가능한 한 빠르게 달라는 요청이다.
   실제 간격은 txt의 dtUs와 헤더 통계로 확인한다.

2. 256Hz는 센서가 정확히 3.906ms마다 보내는 것이 아니다.
   불규칙하게 받은 원본 사이를 선형 보간해 만든 결과다.

3. 평균값을 단순히 사용하는 것이 아니다.
   이전점과 현재점 사이에서 목표 시각의 위치 비율(alpha)을 계산한다.

4. linear 센서 timestamp가 256Hz 생성의 기준 시계다.
   raw와 gravity도 같은 목표 시각에 맞춰 보간된다.

5. 3~7.txt에는 두 종류의 데이터가 같이 들어간다.
   - [원본 수신값]: Android가 실제로 준 값
   - [256Hz 보간값]: 앱이 일정 간격으로 가공한 값

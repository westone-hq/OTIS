# 리빌딩 결정 기록

각 결정은 번호·날짜·내용·근거를 남긴다. 리빌딩 완료 후 학습 자료의 골격이 된다.
RD-14, RD-22~32, RD-34 는 결번이다. RD-34 의 내용(격자 시각 산정 방식)은
RD-35 와 RD-36 본문에 포함되어 있다. 번호가 코드 주석과 다른 문서에서
참조되므로 재배정하지 않는다.

## RD-1 (8/6) 원본 이벤트 스트림을 1차 산출물로 삼는다
기존 구조는 256Hz 보간 스트림이 주 산출물이고 원본은 cache 덤프(부산물)였다.
새 구조는 보간 전 원본이 기준이고 보간은 후처리다.
근거: 앱이 만든 격자 시각으로 앱의 주기를 검증하면 순환 논증이 된다 (기존수집계층 판독서 §1-3).

## RD-2 (8/6) 원본 기록 형식으로 develop raw_native 형식을 채택한다
형식: `type tsUs x_mg y_mg z_mg dtUs`, `#` 줄은 주석.
근거: 간격 판정에 필요한 정보(원본 시각 + 직전 간격)가 정확히 이 구성이며,
develop 브랜치(08ef27a)가 이미 같은 형식으로 실측 파일을 생성 중이라 상호 호환된다.
기존 EVIMP1(가로 20열)은 보간 후 데이터용으로 병존하며 이 형식이 대체하지 않는다.

## RD-3 (8/6) develop 커밋 2건은 cherry-pick 하지 않고 참조로만 쓴다
대상: 96eda7f(명시 주기 요청), 08ef27a(raw_native 덤프).
근거: rebuild 브랜치의 골격화된 sensor_channel.dart 와 충돌하며,
P6·P7 에서 판독서 변경 판정(C1~C7)을 반영해 계승 구현한다.

## RD-4 (8/6) 판독 실패 줄은 0값 대체가 아니라 폐기 + 집계한다
근거: 기존 Dart 수신부는 역직렬화 실패 시 0값 샘플을 만들었고, 이는 Type B 오염
(유령 0 샘플)의 코드 내 재현 경로였다 (판독서 C5).

## RD-5 (8/6) dtUs 는 기록 당시 값을 보존하고, 검증 시 tsUs 차이로 재계산해 대조한다
근거: 같은 정보를 두 경로(네이티브 기록, 사후 재계산)로 갖게 되어
기록 무결성을 파일 자체로 검증할 수 있다.

## RD-6 (8/6) 수집 대상은 raw(accel) + gravity 2종으로 한정한다
motion 은 raw − gravity 로만 산출한다. linear(TYPE_LINEAR_ACCELERATION)는
검증되지 않았으므로 수집·산출·저장 어디에도 쓰지 않는다.
채택 여부는 raw−gravity 대비 검증 후 별도 결정한다.
NativeEventType.linear 는 develop 생성 파일과의 판독 호환을 위해서만 유지한다.
근거: 검증된 파이프라인은 Raw − Gravity = Motion (골든 픽스처로 확인).
linear 는 기존 코드의 관행이었을 뿐 검증 이력이 없다.

## RD-7 (8/6) 간격은 같은 이벤트 종류끼리만 계산한다
raw(accel)와 gravity 는 한 스트림에 섞여 도착하므로, 종류 구분 없이 간격을 재면
실제 주기의 절반 수준 값이 나와 판정을 왜곡한다.
근거: raw_native 파일 구조 (종류가 인터리브로 기록됨).

## RD-8 (8/6) 실측 주기는 평균이 아니라 중앙값으로 추정한다
운영체제의 간헐적 지연이 만드는 소수의 큰 간격이 평균을 밀어
주기를 실제보다 낮게 추정하게 만든다. 중앙값은 이에 강건하다.
근거: 측정 — 기존 로그에서 콜백 지연 스파이크 확인됨.

## RD-9 (8/6) 수집 시작 실패는 화면으로 예외를 던지지 않는다
실패 원인은 lastCaptureError 에 보존하고, 사용자 안내는 측정 화면의
3초 미수신 타임아웃이 담당한다.
근거: 화면(measuring_screen)은 수정 금지 계약 상태이며 startCapture 를
try 없이 await 하므로, 예외를 던지면 화면이 깨진다. 기존의 조용한 삼킴과 달리
원인을 보존하므로 추적은 가능하다.

## [폐기] RD-10 (8/6) motion 합성은 최근 gravity 값 유지(영점 유지) 방식으로 한다
raw 이벤트마다 가장 최근에 도착한 gravity 를 붙여 raw − gravity 를 계산한다.
gravity 확보 전 raw 는 폐기·집계한다.
근거: gravity 는 저주파 성분이라 수 밀리초 유지로 인한 오차가 측정 대역에서
무시 가능하며, 보간과 달리 원본 값이 그대로 보존된다. 필요 시 시각 보간으로의
전환 여부는 실측 대조 후 판단한다.
[폐기] 2026-08-08 — RD-35 로 대체. 직전 gravity 값 유지는 결과에 계단
성분을 남기고 격자 환산으로 제거되지 않는다.

## RD-11 (8/6) 화면·엔진에 주는 샘플의 tsUs 는 실제 센서 시각이다
기존 구조의 보간 격자 시각을 폐기한다 (판독서 D1). 샘플 간격은 불균일하며,
등간격이 필요한 후처리는 이 시각을 근거로 별도 수행한다.

## RD-12 (8/6) 우회·재작성으로 무효화된 기존 테스트는 사유를 적어 보류한다
삭제하지 않고 @Skip 으로 보류하며, 주석에 무효 사유와 복원 조건을 남긴다.
근거: 전체 테스트가 항상 실패 상태면 이후 실제 회귀가 묻힌다.
보류 목록:
- test/domain/auth_test.dart (원인 A - 로그인 우회)
- test/features/auth/login_screen_test.dart (원인 A - 로그인 우회)
- test/features/settings/settings_and_email_test.dart (원인 A - 로그인 우회)
- test/widget_test.dart (원인 C - sensor_channel 재구현)

## [폐기] RD-13 (8/6) startCapture 기본값 256·85.0 은 계약 고정값으로 당분간 유지한다
UI 계약(ui_contract.md §2.5)이 시그니처 기본값을 고정하고 있어 지금은 옮길 수 없다.
계약 해제(UI 분해) 시 CaptureConfig 참조로 이관한다.
근거: 주석 규칙 "숫자는 설정 파일에만"과의 충돌을 인지한 상태의 의도적 예외.
[폐기] 2026-08-08 — RD-33 으로 대체. 네이티브에서 256 을 제거했고,
계측 경로에서 소음 오프셋(85.0) 전달도 제거했다. 소음 값 자체는
NoiseCaptureHandler 기본값으로 유지되며 소음 열 구현 시 다시 연결한다.

## RD-15 (8/6) 원본 기록은 네이티브가 콜백 시점에 직접 쓴다
채널 전송과 무관하게, 콜백 도착 즉시 파일에 기록한다. 채널·Dart 쪽 문제가
있어도 원본은 남는다. 저장 위치는 앱 외부 파일 디렉터리(getExternalFilesDir)
— USB 연결로 PC 복사가 가능하고 OS 가 임의 삭제하지 않는다.

## RD-16 (8/6) 간격 통계는 명령줄 도구로 산출한다 (tool/interval_report.dart)
측정 파일을 PC 로 복사한 뒤 dart run 으로 실행하면 종류별 간격 통계와
기록 무결성 대조 결과를 출력한다. 앱 화면에 통계를 넣지 않는 이유:
판정 자료는 재실행·재검증 가능해야 하며, 화면 표시값은 근거 자료가 될 수 없다.

## RD-17 (8/6) 기능과 연결을 두 층으로 분리한다
기능(lib/domain/capture/ 등 새 폴더)은 순수 로직으로 UI·채널을 모른다.
연결(measurement_engine 등 UI 계약 경로의 파일)은 시그니처만 유지하는
어댑터로, 본문은 기능 호출 또는 미구현 예외다.
연결 파일의 경로는 UI 가 import 하고 있어 UI 분해 단계까지 이동하지 않는다.
현재 연결 파일: measurement_engine, measurement_repository, prefs_store,
parse_raw, report_generator, sensor_channel(구현 완료), auth_repository(우회).

## RD-18 (8/6) 기존 알고리즘 계층과 전용 테스트를 삭제한다
필터·적분·구간검출·지표·내보내기 7개 파일과 전용 테스트 11건을 삭제한다.
학습·대조가 필요하면 main 브랜치와 git 이력에서 본다.
근거: 검증·이해 없이 유지되는 코드는 리빌딩 취지에 어긋나며,
어댑터화된 연결 파일이 남아 있어 컴파일·계약에는 영향이 없다.

## RD-19 (8/6) prefs_store 어댑터만 예외 대신 빈값을 돌려준다
홈 화면 진입이 loadLastSite 에 걸려 있어, 예외를 던지면 측정 화면 도달이
불가능해 수집 실측 자체가 막힌다. 진입 경로에 있는 이 어댑터만
무해한 빈값(null, 빈 Map)으로 통과시킨다.

## RD-20 (8/6) 측정 종료 시점의 예외는 의도된 상태다
analyze 가 미구현이므로 종료 버튼에서 예외가 난다. 원본 기록 파일은
정지(stopCapture) 시점에 이미 저장되므로 실측 자료 확보에는 지장이 없다.
신호 처리 계층 리빌딩에서 해소된다.

## RD-21 (8/7) 최상위 폴더를 역할로 분리한다: ui / domain / adapter / model
ui = 화면 전부. domain = 기능(순수 로직, 리빌딩 산출물). adapter = UI 계약을
유지하는 연결 계층. model = UI 와 기능이 함께 쓰는 데이터·값 정의.
UI 파일의 변경은 import 줄로 한정했다.
참고: docs/ui_contract.md 의 파일 경로 표기는 이동 전 배치 기준이며,
심볼·시그니처 계약 자체는 그대로 유효하다.

## RD-33 (8/8) 네이티브 요청 주기를 SENSOR_DELAY_FASTEST 로 고정한다
목표 주기(256Hz)는 Dart 격자에서 정하고, 네이티브는 단말이 줄 수 있는 최대
속도로 받아 그대로 넘긴다. Kotlin 에서 256 을 제거한다.
근거: 측정 — 요청 주기를 낮추면 시스템이 하드웨어 주기의 정수배로 솎아 내려보낸다.
검증 기기 실측(accel 2374.785us / 421.23Hz)에서 128Hz 요청 시 210.5Hz(2배),
64Hz 요청 시 70.18Hz(6배). 특정 Hz 를 요청하면 최대 속도를 잃는다.
격자 환산은 원본이 격자보다 빨라야 성립한다.

하드웨어 주기는 기기마다 다르므로 특정 값을 전제하지 않는다. 실측 기록:
  검증 기기   accel 2374.785us (421.23Hz) / gravity 4749.570us (210.55Hz)
  대상 기기   accel 2124.5us  (470.70Hz) / gravity 5000.0us  (200.00Hz)
두 채널의 비율도 기기마다 다르다. 검증 기기는 정확히 2배였으나 대상 기기는
2.35 로 무관하다. 따라서 채널 간 비율을 가정한 처리를 하지 않는다.
미확인: gravity 200.000Hz 가 센서 허브 설계값인지 다른 제한인지는 minDelay
조회로 확인해야 한다. accel 이 470Hz 로 200Hz 를 넘으므로 권한 상한만으로는
설명되지 않는다. 결론에는 영향이 없다.

## RD-35 (8/8) raw 와 gravity 를 각각 격자 환산한 뒤 빼서 motion 을 만든다
직전 gravity 값을 재사용하지 않는다. RD-10(영점 유지)을 폐기한다.
근거: 직전 값 재사용은 결과에 계단 성분을 남기고 격자 환산으로 제거되지 않는다.
gravity 는 중력 방향 성분으로 저역 신호이므로 "두 실측 사이에서 부드럽게
변했다"는 가정이 "직전 값에 정지했다"는 가정보다 타당하다.
근거: 측정 — 대상 기기 실측(20260809-170017_raw.txt)에서 gravity 채널의
크기는 1000mg 로 고정(변동 2.8e-4 mg)이고 축별 값만 변한다. 즉 크기 정보가
없는 정규화된 방향 벡터다. 방향 변화 속도는 5ms 당 평균 0.063도,
초당 12.7도 수준으로 1Hz 미만의 저역이며 200Hz 로 담기에 충분하다.
이 실측이 위 가정의 근거이며, 채널 간 비율에 의존하지 않으므로 기기가 바뀌어도
같은 처리가 성립한다.

## RD-36 (8/8) 격자 범위는 두 채널 공통 구간으로 제한하고 밖은 만들지 않는다
t0 = max(raw 첫 시각, gravity 첫 시각), tEnd = min(raw 마지막, gravity 마지막).
범위 밖 격자점은 직전 값을 복사하지 않고 생성하지 않으며, 잘린 행 수를 집계한다.
근거: 보간은 앞뒤 실측값 사이에서만 성립한다. 직전 값 복사는 파일에서 실측과
구분할 수 없다. RD-4(폐기하고 집계, 0값 대체 금지)와 같은 방향이다.
근거: 측정 — 대상 기기 실측에서 headTrimmedRows 2, tailTrimmedRows 1 로
전체 6,362행 중 3행이며, 두 채널의 수신 개시·종료 시점 차이에서 발생한다.

## RD-37 (8/8) 이번 산출물은 3열이며 EVIMP1 로 표기하지 않는다
포맷 식별자를 OTIS-VIB3 으로 하고 X/Y/Z 3열만 쓴다. 소음 열은 보류한다.
근거: 인용 — 참조 파일 H6N1AP65.txt 는 1줄 EVIMP1, 2줄 256, 3줄부터
X Y Z 소음 4열, 줄바꿈 CRLF, 소수점 최대 3자리(뒤 0 제거), 시간 열 없음.
3열 파일에 EVIMP1 을 쓰면 판독 측이 4열로 읽어 어긋난다.
소음은 dBFS 를 dBA 로 바꾸는 오프셋 85.0 의 근거가 없어 소음계 대조 후 추가한다.
소음 열이 붙어 4열이 되는 시점에 식별자를 다시 정한다.

## RD-38 (8/8) 종료 직전 약 30ms 구간은 원본 파일에만 남는다
_cleanup 이 구독을 취소한 뒤 stopCapture 가 실행되는 사이에 도착한 이벤트는
네이티브가 파일에는 쓰지만 Dart 로 전달되지 않는다.
근거: 측정 — 대상 기기 실측에서 원본 파일 accel 11,719 / gravity 4,977 인데
집계는 11,704 / 4,971 로 각각 15건·6건 적다. 폐기 집계는 전부 0 이다.
시간으로는 각각 32ms·30ms 로 같은 구간이다.
자료 손실은 아니다. 원본 파일에 전부 남아 있고, 원본으로 격자 환산을 재현하면
앱보다 8행이 더 나온다(30ms ÷ 3.906ms).
전달되지 않은 건수를 세는 집계 항목이 없다. 추가는 다음 회차로 미룬다.

## RD-39 (8/8) 계측 경로에서 소음 인자 전달을 제거한다
측정 화면과 채널 어댑터가 소음 보정 오프셋을 네이티브로 넘기지 않는다.
소음 수집 자체는 NoiseCaptureHandler 기본값으로 유지한다.
근거: 소음 열은 dBFS 를 dBA 로 바꾸는 오프셋 85.0 의 근거가 없어 이번 범위에서
제외했다. 값을 쓰지 않는데 계측 경로가 계속 전달하면 계측과 소음의 경계가
흐려진다. 이 변경으로 MetricsConfig 가 계측 경로에서 완전히 분리된다.
소음 열 구현 시 오프셋 근거를 확보한 뒤 다시 연결한다.

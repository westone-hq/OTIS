파일에 새 항목을 더하고 바뀐 항목에 "되돌림" 을 적는다.

- 소음(2026-10-20): 표본마다 A 가중(IEC 61672-1, 44.1kHz 2차 필터 3단,
  `NoiseCaptureHandler.A_WEIGHTING_SOS`)을 건 뒤 창 RMS · Fast 평활에 오프셋
  105.2(`kDefaultMicDbfsToDbaOffset`)를 더한다. 녹음(`noise.m4a`)은 가중 전
  소리다. result.json 처리 방식 끝 `+noise(A,fast,+105.2)` 가 없는 전 결과는
  A 가중 없이 +87.3 이다. 테스트폰 · 오티스폰 동시 기록 3건에서 오티스와의
  상관 0.88 ~ 0.90 → 0.96 ~ 0.98, 정면 기록은 평균 · 최대가 0.2 dB 안으로
  맞고 나머지 둘은 조용한 구간이 ±5 dB 갈린다. 오프셋은 임시값이다 — 두 폰을
  같은 자리 · 같은 방향에 두고 다시 재 확정하고, 폰마다 마이크 감도가 달라
  기기별 보정이 필요할 수 있다(`noise_otis_offset_notes.md`).
  2026-10-22: 마이크를 48000Hz(못 열면 44100Hz, A 가중 계수 두 벌)로 바꿨다.
  처리 방식 `+noise(A,fast,+105.2,48000Hz)`, meta.txt `noiseTimeWeighting` ·
  `noiseSampleRateHz` · `noiseOffsetDb`. 오프셋 105.2 는 44.1kHz 때 맞춘 값이라
  다시 확인한다(`docs/pending_checks.md`). 시간가중은 Fast(0.125초,
  `kNoiseTimeWeightSec` = 코틀린 `FAST_TIME_WEIGHT_SEC`) 그대로이고 소음
  평균 · 최대 · 2쪽 차트 · 최대 표시점 모두 저장된 Fast 열이다(저장된
  `noiseMax` 를 그대로 읽는다). 같은 날 Slow(1초)를 수집에, 그다음 최대에만
  걸었다가 되돌렸다 — 2026-10-21 동시 측정 3회 소음열을 시간 맞춰 겹치면
  (오프셋 뺀 뒤) 오티스폰 열 모양이 앱 Fast 열과 곡선 RMSE 1.2 ~ 1.6 dB 로
  맞고 Slow 는 2.4 ~ 3.1 dB 로 나쁘다. 최대 차이 Fast +0.1 / +2.1 / +3.9 dB,
  Slow −5.7 / −1.7 / −3.5 dB 로 Slow 가 PDF 최대와 맞은 것은 우연이고,
  ride_reference 는 Fast 최대 48.7 이 원본과 같다(이미 OTIS 처리된 열). 1회의
  +5.3 dB 중 +3.2 dB 는 폰 위치 오프셋, 나머지 2 ~ 4 dB 는 개발폰 마이크가
  순간 소리를 더 크게 잡는 차이로 보고 코드로 맞추지 않는다. 마이크 입력은
  `MediaRecorder.AudioSource.MIC` 다(기기에 따라 자동 이득 · 잡음 억제가 걸릴
  수 있다). 계수 · 평활은 `noise_weighting_test` 가 SciPy 픽스처(`--noise`)와
  코틀린 소스 상수를 대조한다.

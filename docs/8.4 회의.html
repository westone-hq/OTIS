코드 1FASTEST 와 3000 — 동시에 등록03 / 06
android/.../SensorStreamHandler.kt · start()
// 요청 주기 상수 — Android는 µs 단위. 3ms 요청 = 3000µs
private const val SAMPLING_PERIOD_US = 3000   // 보장값 아님 · desired delay

// [A] ≈3~7ms 쪽 — “가능한 한 빨리” (문서: FASTEST = 0µs delay)
sensorManager?.registerListener(             // SensorManager 공식 API
    this,                                    // ① 리스너(분석 256Hz + 원본 덤프)
    linearSensor,                            // ② 구독할 센서
    SensorManager.SENSOR_DELAY_FASTEST       // ③ FASTEST 상수
)

// [B] 1~3ms 쪽 — 3ms를 숫자로 명시 (API 11+ µs 직접 지정 가능)
sensorManager?.registerListener(             // 같은 API, 세 번째 인자만 다름
    listener1to3,                            // ① 원본 덤프 전용 리스너
    linearSensor,                            // ② 동일 센서(비교용)
    SAMPLING_PERIOD_US                       // ③ 3000µs = 3ms 요청
)

왜 이 코드를 썼나

registerListener의 세 번째 인자는 desired delay(µs)입니다. FASTEST 상수와 숫자 3000은 둘 다 공식 방식입니다. 동시에 걸어 실측 차이를 비교했습니다.

코드 2요청 ≠ 실측 · timestamp로 확인04 / 06

// samplingPeriodUs = "desired delay" (원하는 지연)
// → 하드웨어가 무조건 그 간격으로 준다는 뜻이 아님
// 실제 간격은 연속 이벤트의 timestamp 차이로 확인

// SensorEvent.timestamp 단위 = nanoseconds (공식)
val dtUs = (event.timestamp - prevTimestamp) / 1000
//          └ 현재 이벤트 시각(ns)  ┘  └ 이전 시각(ns) ┘  ÷1000 → µs
val dtMs = dtUs / 1000.0                    // µs → ms (초별 파일 dt_ms 컬럼)
// 이번 실측: dtMs ≈ 2.375  (요청 3.000과 다름, FASTEST와 동일)

// 새 센서 이벤트가 있을 때 Android가 호출하는 공식 콜백
override fun onSensorChanged(event: SensorEvent?) {
    if (event == null) return                 // null이면 즉시 종료

    when (event.sensor.type) {               // 어떤 센서 이벤트인지 분기
        Sensor.TYPE_ACCELEROMETER -> {       // 중력 포함 → 파일 type "raw"
            dump.append(
                "raw",                       // 파일 type (=예전 rawX/Y/Z)
                event.timestamp,             // 발생 시각(ns) · dt_ms 기준
                event.values[0],             // X축 m/s²
                event.values[1],             // Y축 m/s²
                event.values[2]              // Z축 m/s² · 승차감 주축
            )                                // 0/1/2 순서는 Android 규격
        }
        Sensor.TYPE_GRAVITY -> { ... }       // → "gravity"
        Sensor.TYPE_LINEAR_ACCELERATION -> { // → "linear" · 분석 주축
            ...
        }
    }
}

왜 이 코드를 썼나

센서 수신의 표준 진입점입니다. timestamp·values는 SensorEvent 공식 필드입니다.

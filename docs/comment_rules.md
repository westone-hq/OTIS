| # | 규칙 | 한 줄로 |
|---|---|---|

> **무엇을 하는지 / 왜 하는지 / 어떤 값이 나오는지** 를 알 수 있으면 충분하다.

# 본문

## 1. 얼마나 쓸지 정하기

먼저 이 함수가 어느 쪽인지 고른다.

| 이 함수는 | 등급 | 적을 것 |
|---|---|---|
| 숫자를 계산해서 내놓는다 | 1 | 목적 · 인자 · 반환 · 근거 |
| 그중 **수식이나 상수를 어디선가 가져왔다** | 1+ | 위 + `식:` 줄 |
| 데이터를 옮기거나 상태를 바꾼다 | 2 | 목적 한 줄 |
| 내부에서만 쓰는 보조 함수다 | 3 | 안 적음 |

**왜 나누는가:** 모든 함수에 네 줄을 요구하면 지켜지지 않는다. → 부록 A-1
**예시:** → 부록 B-1 ~ B-4

---

## 2. 무엇을 적을지

| 줄 | 적을 내용 |
|---|---|
| `목적:` | 무엇을 하는지 + **왜 하는지** |
| `인자:` | 이름 — 의미 (단위), 쓸 수 있는 범위 |
| `반환:` | 의미 (단위) + **값이 없거나 계산이 안 될 때 어떻게 되는지** |
| `식:` | 코드로 바꾸기 **전의 원래 식**. 원문 기호 그대로 |
| `근거:` | 아래 3번 |

**주의할 점**

- 판단이 들어간 선택(평균 대신 중앙값, 창 길이 1초 등)은 **왜 그렇게 골랐는지 적는다**
- 함수 이름을 한글로 옮겨 적은 것은 목적이 아니다
- 다른 함수 이름만 가리키지 않는다. 주석 읽으려고 다른 파일을 열면 안 된다

→ 부록 A-2 (`식:` 줄이 왜 따로 필요한가), 부록 A-4 (나쁜 예 / 좋은 예)

---

## 3. 근거 적기

### 3-1. 네 가지 중 하나를 고른다

| 적는 말 | 쓰는 경우 |
|---|---|
| `근거: 표준` | 표준 문서에서 가져옴 |
| `근거: 인용` | 논문 · 책 · 남의 코드 · 공식 문서에서 가져옴 |
| `근거: 측정` | 우리가 측정해서 정함 |
| `근거: 미정` | 아직 근거가 없음 |

### 3-2. 찾아갈 수 있을 만큼 적는다

> **그 문서를 처음 여는 사람이, 이 주석만 보고 해당 페이지를 펼칠 수 있는가.**

| 종류 | 반드시 적을 것 |
|---|---|
| 표준 문서 | 표준 번호 + 판·연도 + **절 또는 표·식 번호** |
| 논문 · 책 | 저자 + 제목 + 연도 + 절 또는 페이지 |
| 웹 문서 · 남의 코드 | 사이트·저자 + 문서 제목 + **접속 날짜** |
| 사내 측정 | 데이터 파일명 + 날짜 + 담당자 |
| 미정 | **담당자 + 기한** |

문서 이름만 적는 것은 출처가 아니다. → 부록 A-3

### 3-3. `근거: 미정`이 핵심이다

모든 값에 근거를 만들어내라는 뜻이 아니다.
**근거 없는 값을 근거 있는 척 두지 말자는 뜻이다.**

## 4. 이름과 숫자

| 규칙 | 내용 |
|---|---|
| 값 이름 | 뒤에 **단위를 붙인다.** `interval` 이 아니라 `intervalUs` |
| 숫자 | 설정 파일에만 적는다 |
| 숫자 예외 | 0, 1, -1 / 수식 안의 상수는 `식:` 줄에 원래 식이 있으면 그대로 |

이름에 단위가 있으면 인자 설명이 거의 필요 없어진다. 주석을 줄이는 가장 효과적인 방법이다.

→ 부록 B-5 (단위 붙인 이름 모음), 부록 A-5 (숫자를 모아두는 이유)

| 규칙 | 내용 |
|---|---|
| 줄임말 | 파일 안에서 **처음 한 번은 풀어 쓴다** |
| 외부 용어 | 원문과 번역을 같이 적는다. 순서는 파일 안에서 통일 |

→ 부록 A-4

## 6. 적지 않는 주석

| 안 적는 것 | 이유 |
|---|---|
| 코드를 그대로 다시 적은 주석 | 정보가 늘지 않는다 |
| 수정 이력 · 날짜 · 담당자 | 깃(Git)이 관리한다 |
| 주석 처리한 옛 코드 | 지운 코드는 삭제한다 |
| 담당자·기한 없는 `할 일` | `근거: 미정` 으로 통일 |

| 상태 | 표시 |

**`확인: 안 함`이 남아 있는 코드는 회의에서 설명하지 않는다.**

작성자 본인은 이미 알고 있어서 판단이 안 된다.

# 부록 A. 규칙 설명

## A-1. 왜 등급을 나누는가

모든 함수에 네 줄을 요구하면 지켜지지 않는다.

"파일에 저장한다" 같은 함수에까지 인자·반환·근거를 적게 하면,
곧 아무 의미 없는 주석이 기계적으로 붙는다. 그러면 아무도 주석을 읽지 않게 된다.

**설명이 필요한 곳에만 분량을 쓴다.**

- 숫자가 나오는 함수는 **틀려도 조용히 틀린다.** 값은 나오는데 그 값이 틀리다. 그래서 설명이 필요하다
- 데이터를 옮기는 함수는 틀리면 바로 드러난다. 그래서 한 줄이면 된다

---

## A-2. 왜 `식:` 줄이 따로 필요한가

코드는 수식을 그대로 담지 못한다.
계산을 여러 줄로 쪼개고, 변수 이름을 바꾸고, 순서를 바꾸기 때문이다.

그래서 **코드만 봐서는 원래 식이 무엇이었는지 되짚을 수 없다.**
원문 문서를 옆에 놓고 대조하려 해도, 기호가 달라서 어느 항이 어디에 해당하는지 알 수 없다.

`식:` 줄을 적을 때 지킬 것.

| 지킬 것 | 이유 |
|---|---|
| 원래 문서의 기호를 그대로 쓴다 | 문서와 코드를 나란히 놓고 대조할 수 있어야 한다 |
| 기호와 코드 변수명이 다르면 대응을 적는다 | 예: `w0 → omega0` |
| 여러 줄이면 여러 줄로 적는다 | 한 줄로 욱여넣으면 아무도 못 읽는다 |
| 단위가 있는 값은 단위를 적는다 | |

---

## A-3. 출처 표기 — 나쁜 예 / 좋은 예

| 나쁨 | 좋음 |
|---|---|
| `근거: 표준 — ISO` | `근거: 표준 — ISO 8041-1:2017, 6.2절 표 3` |
| `근거: 인용 — 인터넷` | `근거: 인용 — Android 개발자 문서 "Motion sensors", 접속 2026-08-05` |
| `근거: 측정 — 실측` | `근거: 측정 — 기준파일 2024F1447R01, 8/5 대조, 박건준` |
| `근거: 미정` | `근거: 미정 — 마이크 보정값, 소음계 대조 필요, 박희정, 8/11` |

**웹 문서에 접속 날짜를 적는 이유:** 웹 문서는 내용이 바뀌거나 사라진다.
날짜가 있으면 나중에 내용이 달라졌을 때 그 사실을 알 수 있다.

**미정에 담당자와 기한을 적는 이유:** 적어두지 않으면 아무도 가져가지 않는다.
미정이라고 적어두면 나중에 검색해서 한 번에 찾을 수 있지만,
아무 표시 없이 두면 그 값은 영원히 근거가 있는 값으로 오해된다.

---

## A-4. 표현 — 나쁜 예 / 좋은 예

### "무엇을"만 쓰고 "왜"를 안 쓴 경우

| 나쁨 | 좋음 |
|---|---|
| `목적: 중앙값을 구한다.` | `목적: 중앙값으로 실제 수집 주기를 구한다. 평균을 쓰지 않는 이유는 운영체제가 가끔 값을 늦게 주는데, 그 몇 개가 평균을 크게 밀어버리기 때문이다.` |

판단이 들어간 선택은 **다른 선택지가 있었다는 뜻**이다.
이유가 없으면 나중에 바꿔도 되는 값인지 아닌지 아무도 모른다.

### 줄임말을 안 푼 경우

| 나쁨 | 좋음 |
|---|---|
| `P2P 값` | `최대·최소 차이 (peak to peak)` |
| `HPF 적용` | `고역통과 필터 (high-pass filter) 적용 — 낮은 주파수를 걸러낸다` |
| `dBA` | `A 가중 소음 크기 (dBA) — 사람 귀 감도에 맞춰 보정한 값` |

같은 파일 안에서 두 번째부터는 줄임말만 써도 된다.

### 다른 함수 이름만 가리킨 경우

| 나쁨 | 좋음 |
|---|---|
| `목적: applyFilter를 호출한다.` | `목적: X·Y축에 수평 진동 가중 필터를, Z축에 대역 제한 필터를 적용한다.` |

---

## A-5. 왜 숫자를 설정 파일에만 두는가

숫자가 코드 곳곳에 흩어지면 나중에 회수할 수 없다.
"우리가 쓰는 값이 뭐뭐 있느냐"는 질문에 답하려면 전체 코드를 뒤져야 한다.

설정 파일 하나에 모아두면 **그 파일만 보여주면 설명이 끝난다.**
값을 바꿔가며 실험하는 일도 개발 작업이 아니라 설정 변경이 된다.

---

## A-6. 왜 AI 코드를 표시하는가

AI가 만든 코드는 **그럴듯하게 틀린다.** 문법도 맞고 이름도 맞는데 값이 틀린다.
읽어서는 발견되지 않고, 값을 넣어 대조해야만 드러난다.

표시를 남기는 이유는 두 가지다.

1. 확인한 것과 확인 안 한 것을 구분하기 위해
2. 확인 안 한 코드를 실수로 설명하는 일을 막기 위해

**이름을 근거로 삼지 않는다.**
이전에 "10Hz 필터"라고 이름 붙인 코드의 실제 차단 지점이 4.2Hz였던 일이 있었다.
이름과 실제 동작은 다를 수 있다.

손으로 계산 가능한 입력을 하나 만들어 결과를 대조하고, 그 결과를 `근거: 측정` 으로 남긴다.

## B-1. 등급 1 — 숫자를 계산하는 함수

```dart
/// 목적: 값 목록의 표준편차를 구한다.
///       측정값이 얼마나 흩어져 있는지 보기 위해 쓴다.
/// 인자: valuesC — 온도 값 목록 (섭씨, 2개 이상)
/// 반환: 표준편차 (섭씨). 목록이 2개 미만이면 0
/// 근거: 측정 — 흩어짐 판정 기준, 8/5, 홍길동
double stdDevC(List<double> valuesC) {
  if (valuesC.length < 2) return 0;
  final mean = valuesC.reduce((a, b) => a + b) / valuesC.length;
  final sumSq = valuesC
      .map((v) => (v - mean) * (v - mean))
      .reduce((a, b) => a + b);
  return sqrt(sumSq / (valuesC.length - 1));
}
```

## B-2. 등급 1+ — 수식을 가져온 함수

```dart
/// 목적: 기온과 풍속으로 체감온도를 구한다.
///       바람이 불면 실제 기온보다 춥게 느껴지는 것을 수치로 나타낸다.
/// 인자: tempC   — 기온 (섭씨, 10 이하에서만 유효)
///       windKmh — 풍속 (킬로미터/시, 5 이상에서만 유효)
/// 반환: 체감온도 (섭씨). 유효 범위를 벗어나면 tempC 를 그대로 돌려준다
/// 식:   T_wc = 13.12 + 0.6215·T - 11.37·V^0.16 + 0.3965·T·V^0.16
///         T = 기온 (섭씨),  V = 풍속 (킬로미터/시)
///         T_wc → 반환값,  T → tempC,  V → windKmh
/// 근거: 인용 — 캐나다 기상청(Environment Canada) 체감온도 산식,
///       "Wind Chill Index" 문서, 접속 2026-08-05
double windChillC(double tempC, double windKmh) {
  if (tempC > 10 || windKmh < 5) return tempC;
  final v16 = pow(windKmh, 0.16);
  return 13.12 + 0.6215 * tempC - 11.37 * v16 + 0.3965 * tempC * v16;
}
```

**여기서 볼 것**

- 원래 식의 기호(`T`, `V`, `T_wc`)를 그대로 적고, 코드 변수와의 대응을 따로 적었다
- 식에 나오는 상수(13.12, 0.6215 등)는 설정 파일로 빼지 않았다. `식:` 줄에 원래 식이 있기 때문이다
- 유효 범위를 벗어났을 때 어떻게 되는지 `반환:` 줄에 적었다

| `duration` | `durationSec` | 초 |
| `distance` | `distanceM` | 미터 |
| `speed` | `speedMs` | 미터/초 |
| `temp` | `tempC` | 섭씨 |

**붙이는 방법:** 단위를 짧게 줄여 이름 뒤에 붙인다.
마이크로초는 `Us`, 헤르츠는 `Hz`, 미터는 `M`, 초는 `Sec`.

두 단위가 겹치면 순서대로 붙인다. 예: 미터/초 → `speedMs`

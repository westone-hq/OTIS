# OTIS V-Check 요구사항 정리표 (현재 기능)

2026-10-26 main 기준으로 앱에 들어 있는 기능을 빠짐없이 모은 표다. 모두
구현되어 실기기에서 확인을 마쳤다. 세부 수치 · 이유는 각 spec
(`docs/spec/app_behavior.md` · `docs/spec/signal_processing.md` ·
`docs/spec/report.md`)과 `docs/release.md` 에 있고, 이 표는 "무엇을 하는가"
만 적는다. 기능이 바뀌면 이 표도 같이 고친다.

---

## 1. 앱 공통

| ID | 기능 | 요구사항 |
|---|---|---|
| APP-01 | 앱 이름 · 패키지 | 홈 화면 아이콘 아래 이름은 "OTIS V-Check". 패키지 이름 `com.otis.vibration_checker` 는 바꾸지 않는다(바꾸면 업데이트가 이어지지 않는다) |
| APP-02 | 대상 기기 | 일반 안드로이드 폰. 가속도 · 중력 센서가 모두 있어야 측정할 수 있다 |
| APP-03 | 화면 흐름 | 로그인 → 홈(현장 정보) → 시작(대기 시간 · 거치 안내) → 측정 → 결과. 홈에서 저장 결과 목록 · 설정으로 간다 |
| APP-04 | 한국 시간 | 리포트 머리말 · 측정 ID · 목록 · 결과 화면 · 메일 제목의 시각은 기기 시간대와 상관없이 한국 시간이다 |
| APP-05 | 현장용 글자 · 버튼 크기 | 본문 18sp 이상, 캡션 16sp 이상, 터치 영역 56dp 이상, 주 버튼 64dp |
| APP-06 | 키보드 · 시스템 막대 | 로그인 버튼은 키보드 위로 올린다. 바텀 시트는 아래쪽 시스템 막대를 비켜 준다 |
| APP-07 | 권한 | 고속 센서 · 마이크 · 화면 켜짐 유지 · 진동 · 인터넷 · 앱 설치 권한을 쓴다 |

## 2. 로그인 · 작업자

| ID | 기능 | 요구사항 |
|---|---|---|
| LGN-01 | 사번 로그인 | 사번 + 비밀번호로 로그인한다. 비밀번호 = 사번이다 |
| LGN-02 | 입력 맞춤 | 대소문자 · 앞뒤 공백 · 전각 문자를 가리지 않고, 한글 자판으로 친 낱자도 영문으로 바꿔 비교한다("ㅅ" → "T"). 입력칸은 영문 · 숫자 키보드를 띄운다 |
| LGN-03 | 오류 안내 | "사번을 입력하세요" · "등록되지 않은 사번입니다" · "비밀번호를 입력하세요" · "비밀번호가 맞지 않습니다" 를 칸별로 보인다 |
| LGN-04 | 작업자 명단 | 명단은 앱 안 자산(`assets/workers/workers.json`)이다. OTIS 명단 엑셀에서 `tool/import_workers.py` 로 만들고, 바뀌면 앱을 새로 배포한다 |
| LGN-05 | 명단을 못 읽을 때 | 앱은 띄우되 로그인을 누르면 "작업자 명단을 읽지 못했습니다" 와 사유(몇 번째 항목의 어느 칸인지)를 보인다 |
| LGN-06 | 로그인 유지 | 한 번 로그인하면 기기에 남아 앱을 다시 켜도 유지된다. 새 명단에서 빠진 사번이면 로그아웃시킨다 |
| LGN-07 | 로그인 전 차단 | 로그인 전에는 모든 화면 경로가 로그인 화면으로 돌아간다 |
| LGN-08 | 결과에 작업자 기록 | 측정을 저장하는 시점의 성명 · 사번 · 업체명 · 관리팀을 결과에 싣는다. 나중에 다른 사람이 로그인해도 예전 결과의 이름은 그대로다. OTIS 직원은 업체 · 팀이 비어 있다 |

|---|---|---|
| HOM-01 | 입력 항목 | 제번 · 현장명 · 최하층 / 최상층(지하층은 B1 · B2) · 운전 방향(상승 · 하강) · 기종 · 하중 · 해석 종류(분석 내용) · 추가 참고사항 |
| HOM-02 | 기종 선택 | 줄-로우프 2:1 · 줄-로우프 1:1 · Gen2(기본) · 유압 · 기타 |
| HOM-03 | 해석 종류 선택 | 일반 · 층간 시험(기본) · 문 열림 사이클 · 브레이크 기능 · 사이클 저크(가속도증가율) 테스트. 기록 · 리포트 표시만 하고 계산은 같다 |
| HOM-04 | 하중 | kg 고정 숫자 입력. 0 보다 커야 한다 |

| HOM-06 | 입력 자동 저장 | 바뀔 때마다 기기에 저장해 다음에 그대로 뜬다. 참고사항은 저장하지 않아 측정마다 빈 칸에서 시작한다 |
| HOM-07 | 메뉴 | 저장 결과 목록 · 설정으로 가는 버튼 |
| HOM-08 | 업데이트 확인 | 앱을 켤 때마다 한 번 새 버전을 확인한다(UPD 참고) |

## 4. 측정 준비 — 시작 화면

| ID | 기능 | 요구사항 |
|---|---|---|
| STA-01 | 센서 지원 확인 | 가속도 또는 중력 센서가 없는 기기는 "측정을 지원하지 않습니다" 를 보이고 측정을 막는다 |
| STA-02 | 대기 시간 | 측정 시작 전 대기 3 · 5(기본) · 10 · 15초 중에서 고른다. 아래에 "카운트 다운 후 삐 소리와 함께 측정이 시작됩니다" · "볼륨키를 누르면 삐 소리와 함께 측정이 종료됩니다." · "운행이 멈춘 뒤 1초 기다렸다가 누르세요." 를 굵은 본문으로 보인다 |
| STA-03 | 거치 안내 | "휴대폰을 카 바닥 중앙에 놓으세요" 와 "거치 방법 보기" 그림 시트: 화면을 아래로 뒤집고, 출입구를 바라보고 섰을 때 휴대폰 위쪽이 왼쪽. 삐 소리와 함께 측정이 시작되면 엘리베이터를 움직이고, 멈춘 뒤 1초 기다렸다 볼륨키를 누르면 삐 소리와 함께 끝나며, 측정 중에는 조용히 한다 |
| STA-04 | 마이크 권한 | 측정 화면에 들어가기 전에 마이크 권한을 받는다(측정 중에는 폰이 뒤집혀 있어 누를 수 없다). 거부하면 "진동만 측정" 또는 취소를 고르고, 휴대폰 설정에서 허용하는 길을 안내한다 |

## 5. 측정 — 수집

| ID | 기능 | 요구사항 |
|---|---|---|
| MEA-01 | 카운트다운 | 고른 대기 시간만큼 센 뒤 수집을 시작한다. 끝나기 0.5초 전에 삐 소리를 한 번 낸다. "건너뛰기 / 즉시 시작" 은 바로 삐 소리를 내고 0.5초 뒤 시작한다 |
| MEA-02 | 3축 진동 수집 | 가속도 · 중력 센서를 가장 빠른 주기로 받아 256Hz 격자로 맞춘다. 수직(Z)은 중력 방향 기준이라 폰을 뒤집거나 기울여도 위로 가속 = 양수다 |
| MEA-03 | 소음 동시 수집 | 진동과 함께 마이크로 dBA 를 잰다(NOI 참고) |
| MEA-04 | 경과 시간 · 현재 속도 | 측정 중 걸린 시간과 현재 속도(m/s, 소수 첫째 자리)를 보인다. 첫 1초는 "—". 표시 전용이라 저장하는 최대 속도와 조금 다를 수 있다 |
| MEA-05 | 측정 종료 | 볼륨키(올림 · 내림) 또는 "테스트 완료" 버튼으로 끝낸다. 누른 때부터 0.5초 뒤(수집을 멈춘 뒤) 삐 소리를 한 번 낸다. 시작 · 종료 소리는 녹음 · 소음 값에 들지 않는다 |
| MEA-06 | 화면 꺼짐 방지 | 측정하는 동안 화면이 꺼지지 않게 한다 |
| MEA-07 | 뒤로가기 중단 | 뒤로가기를 누르면 "측정을 중단할까요? 진행 중인 측정 데이터는 저장되지 않습니다" 를 묻고, 중단하면 저장하지 않는다 |
| MEA-08 | 앱 전환 중단 | 측정 중 앱이 백그라운드로 가면(전화 수신 등) 측정을 중단하고, 돌아오면 그 사실을 알린다 |
| MEA-09 | 센서 무응답 중단 | 센서 값이 3초 동안 오지 않으면 측정을 중단한다 |
| MEA-10 | 최소 측정 길이 | 2초보다 짧으면 "N초 이상 측정해 주세요" 로 실패시킨다 |
| MEA-11 | 실패 안내 | 현장 정보 없음 · 센서 데이터 없음 · 파일 생성 실패 · 너무 짧음 · 측정값 처리 실패 · 결과 변환 실패 · 저장 오류를 사유와 함께 알리고 측정을 시작한 화면으로 돌아간다 |
| MEA-12 | 끝나면 결과로 | 성공하면 측정 화면이 결과 화면으로 바뀐다 |
| MEA-13 | 중단 때 정리 | 저장하지 않는 중단이면 안드로이드 원본 기록 · 녹음 파일을 바로 지운다. 실패한 측정의 원본은 그 측정 폴더에 남긴다 |

## 7. 소음 측정 · 현장 소음 녹음

| ID | 기능 | 요구사항 |
|---|---|---|
| NOI-01 | dBA 측정 | 마이크 48kHz(못 열면 44.1kHz) 모노 신호를 A 가중 · Fast(0.125초) 평활하고 오프셋 +105.2 dB 를 더해 dBA 로 낸다 |
| NOI-02 | 소음 지표 | 운행 구간 안 소음 최대 · 평균 |
| NOI-03 | 마이크 없이 측정 | 마이크 권한이 없으면 진동만 재고 소음 지표는 미측정(빈 값)으로 둔다 |
| NOI-04 | 현장 소음 녹음 | dBA 를 재는 같은 마이크 신호를 AAC 64 kbps M4A 로 녹음해 측정 폴더에 `up_NOISE_제번_측정ID.m4a`(하강 `dn_`) 로 남긴다(1분에 약 0.48MB). 대화가 녹음될 수 있다는 점은 알고 넣기로 했다 |
| NOI-05 | 녹음 실패 | 녹음이 실패하거나 정지 때 1초 안에 끝나지 않으면 녹음만 포기하고 dBA 측정 · 저장은 계속한다. 메일 본문에 "누락:" 으로 밝힌다 |

## 8. 신호 처리 · 지표 계산

| ID | 기능 | 요구사항 |
|---|---|---|
| SIG-01 | 격자 환산 | 256Hz 격자로 맞추고 두 센서가 겹친 구간 앞뒤 0.5초를 버린다 |
| SIG-02 | 기준선 0 맞춤 | 첫 1초 평균을 축마다 뺀다. 그 안에서 움직였으면 움직임 앞까지(0.3초 이상), 안 되면 기록 끝 정지 1초를 쓴다 |
| SIG-03 | 저역 · 재표본 | 40Hz 4차 버터워스 양방향 저역 뒤 100Hz 로 재표본한다. 결과는 SciPy 정본과 같아야 한다 |
| SIG-04 | 운행 거리 · 최대 속도 | 가중 전 수직 가속도를 움직인 구간(속도 0.05 m/s 초과, 앞뒤 0.5초 여유)만 적분해 낸다 |
| SIG-05 | 저크 · 가속도 차트 값 | 저크는 1.6Hz 저역 가속도의 차분, 가속도 차트는 10Hz 저역 값(표시용) |
| SIG-06 | 주파수 가중 | ISO 18738 방식: X · Y 는 Wd, Z 는 1Hz 고역 + Wk |
| SIG-07 | 기종 응답 보정 | 보정 표에 있는 휴대폰만 수직에 보정 필터를 건다(지금 갤럭시 S22 `SM-S901…`: 25Hz 2차 저역). 보정 여부는 결과 · 진단 기록에만 남긴다 |
| SIG-08 | 운행 구간 | 출발 · 정지 0.5 m 를 뺀 구간에서 지표를 낸다. 운행이 1 m 이하면 구간을 정하지 못한다 |
| SIG-09 | 진동 지표 | 축마다 반주기 Peak-to-Peak 최대와 A95. 수평은 X · Y 중 큰 값 |
| SIG-10 | 수직 최대 · Jptp | 운행을 정속 · 가감속 구간으로 나눠 수직 최대 = 정속 구간 최대 P2P, Jptp = 가감속 구간(앞뒤 0.4초 넓힘) 최대. 정속이 1초 미만이면 둘 다 "—" |
| SIG-11 | 판정 | 지표마다 황색 · 적색 기준(REP-03)으로 초과 여부를 낸다. 못 잰 지표는 판정도 비운다 |
| SIG-12 | 결과 경고 | 정지 뒤 1초 미만에 종료("정지 후 1초 이상 기다린 뒤 종료하세요") · 출발 직후 움직임("시작 후 2초 기다린 뒤 출발하세요") |
| SIG-13 | 미측정은 빈 값 | 재지 않은 값을 0 이나 빈 문자열로 채우지 않는다 |
| SIG-14 | 예전 결과 읽기 | 처리 방식이 다른 예전 결과(가중 전 · 구간 전 · 저크 필터 전 등)도 그때 값 그대로 읽고 그린다 |

## 9. 저장

| ID | 기능 | 요구사항 |
|---|---|---|
| STO-01 | 측정 한 건 = 폴더 하나 | 앱 저장 공간 `captures/<측정 ID>/`. 측정 ID 는 한국 시간 `yyyyMMdd-HHmmss` |
| STO-02 | 저장 파일 | `result.json`(결과 전부) · `summary.json`(목록용) · `meta.txt`(진단) · `native_raw.txt`(안드로이드 원본)과, 이름에 방향 · 제번 · 측정 ID 가 들어가는 `up_RAW_제번_측정ID.txt`(EVIMP1) · `up_REPORT_제번_측정ID.pdf` · `up_NOISE_제번_측정ID.m4a`(녹음, 하강이면 `dn_`). 2026-10-27 전 측정의 `raw.txt` · `report.pdf` · `noise.m4a` 도 그대로 읽는다 |
| STO-03 | 리포트 미리 만들기 | 저장할 때 PDF 를 만들어 둔다. 실패해도 측정은 저장되고, 나중에 필요할 때 다시 만든다 |
| STO-04 | 보관 개수 | 최근 100건만 남기고 넘으면 오래된 것부터 폴더째 지운다. 방금 저장한 측정은 지우지 않는다. 한 건 약 5MB(44초 운행), 100건이면 약 0.5GB |
| STO-05 | 실패 기록도 남김 | 신호 처리에 실패해도 `raw.txt` · 원본 기록은 남긴다 |
| STO-06 | 깨진 파일 복구 | 목록용 파일이 없거나 깨졌으면 정본에서 다시 만든다. 정본까지 못 읽으면 그 건만 "읽을 수 없는 결과" 로 둔다 |

## 10. 결과 화면

## 15. 앱 안 업데이트

| ID | 기능 | 요구사항 |
|---|---|---|
| UPD-01 | 새 버전 확인 | 배포 저장소(GitHub Releases)의 `version.json` 을 3초 안에 받아 빌드 번호를 비교한다 |
| UPD-02 | 인터넷 없을 때 | 홈의 자동 확인은 못 받으면 조용히 넘어간다(기계실에서도 측정은 막지 않는다). 설정의 확인은 사유를 알린다 |
| UPD-03 | 선택 업데이트 | "업데이트 · 나중에". 나중에를 누르면 같은 버전을 하루 동안 다시 묻지 않는다 |
| UPD-04 | 필수 업데이트 | 최소 빌드보다 낮으면 닫을 수 없고 업데이트해야 쓸 수 있다 |
| UPD-05 | 내려받기 · 검증 | 진행 표시와 함께 받고, SHA-256 이 맞지 않으면 설치하지 않는다 |
| UPD-06 | 설치 | 안드로이드 패키지 설치 세션으로 설치한다. 설치 허용이 꺼져 있으면 설정을 열도록 안내하고, 서명이 달라 덮어쓸 수 없으면 지우고 새로 설치하라고(측정 결과를 먼저 옮기라고) 안내한다 |
| UPD-07 | 측정 중 금지 | 측정 · 결과 화면에서는 확인 · 설치하지 않는다 |

## 16. 데이터 파일 형식

| ID | 기능 | 요구사항 |
|---|---|---|
| FMT-01 | raw.txt | EVIMP1 형식: 머리 두 줄(`EVIMP1`, `256`) 뒤 X Y Z 소음 네 열. 필터 · 기준선 보정 없이 축별 전체 평균만 뺀다. CRLF 줄 끝 |
| FMT-02 | result.json | 현장 정보 · 작업자 · 지표 · 판정 근거 · 시계열 8개(X · Y · Z · 소음 · 위치 · 속도 · 가속도 · 저크) · 처리 방식 문자열 · 운행 구간 · 기종 · 보정 · 거치 · 경고 근거 |
| FMT-03 | meta.txt | 사람이 읽는 진단 기록: 격자 환산 집계 · 기준선 · 처리 구간 · 기종 보정 · 거치 판정 · 파일 옮기기 결과. CRLF 줄 끝 |
| FMT-04 | native_raw.txt | 보간 전 안드로이드 센서 이벤트 원본(종류 · 시각 · X · Y · Z · 간격). 기기에만 남긴다 |

    - 수직 20Hz 저역은 2026-10-22 기종 응답 보정으로 바뀌었다 — 20번을 본다
17. **거치 방향 경고 (2026-10-22)**
    - 화면 위 · 기울여 놓고 측정을 시작하면 약 1.7초 뒤(2026-10-22 2차,
      기준선 구간 뒤로 미룸) 경고음 · 진동이 한 번 나는지(엎어 둔 상태에서
      들리는지), 화면 아래면 나지 않는지, 1.7초 전에 운행을 시작하면 울리지
      않는지
    - 경고음 · 진동이 들어간 raw.txt · noise.m4a 구간이 운행 시작 전인지,
      운행을 바로 시작하는 측정(정지 1초 미만)에서 소음 평균 · 최대에 섞이지
      않는지
    - 알람 소리 통로(STREAM_ALARM)가 무음 · 방해금지 모드에서 어떻게 되는지
    - 진동(알람 용도, 2026-10-22)이 기기 설정의 터치 진동을 끈 상태에서도
      울리는지. 에뮬레이터는 `dumpsys vibrator_manager` 에 `usage: ALARM` 으로
      기록되는 것까지 확인했다
18. **48 kHz 전환 (2026-10-22, 소음은 Fast 그대로)**
    - 실기기에서 48000Hz 로 열리는지(meta.txt `noiseSampleRateHz: 48000`), 못
      여는 기기에서 44100Hz 로 내려가 값이 나오는지
    - **48 kHz 전환 후 오프셋 재확인** — 오티스폰과 같은 자리 동시 측정, 소음
      평균 차이 ±1 dB 안인지(오프셋 105.2 는 44.1 kHz 때 맞춘 값). 개발폰 대
      OTIS PDF 소음 평균: 10-21(44.1 kHz) +2.5 / −0.2 / −1.0(평균 +0.4),
      10-22(48 kHz) 상승 +1.3 · 하강 +2.7(평균 +2.0). 48 kHz 로 바꾼 뒤 약
      1.5 dB 높아졌을 수 있다. 다만 두 날 모두 두 폰을 같은 자리 · 같은
      방향에 두었는지 기록이 없어 폰 위치 차이와 가를 수 없다. 오티스폰
      원시데이터를 앱 경로로 낸 평균도 10-22 상승 51.3(PDF 52.3), 하강
      51.0(52.3)이라 OTIS 쪽 계산과도 1 dB 안팎 다르다
    - noise.m4a 가 48kHz 로 재생되는지, 크기가 1분 0.48MB 안팎 그대로인지
    - 마이크 입력이 `AudioSource.MIC` 라 기기에 따라 자동 이득 · 잡음 억제가
      걸릴 수 있다 — 같은 소리에서 기기별 값 차이를 볼 때 함께 본다
19. **OTIS 최대 속도 표시 규칙 (2026-10-22)** — 정격 속도가 1.5 · 1.75 가
    아닌 현장(예: 1.0 · 2.0 · 2.5 m/s)에서 오티스폰과 동시 측정해, OTIS 표의
    최대 속도가 앱 최대 속도 · 정속 구간 평균(`result.json steadySpeedMps`)
    · 그 0.05 반올림 · 정격 속도 가운데 무엇과 같은지 본다. 2026-10-21 은
    "정속 평균 → 0.05 반올림" 이 7건 모두 맞았지만 OTIS 값이 두 가지뿐이고
    경계 여유가 0.003 이었다
20. **기종 응답 보정 재확인 (2026-10-22)** — 다른 건물 · 다른 승강기에서
    개발폰(갤럭시 S22) · 오티스폰 동시 측정(상승 · 하강, 두 폰 모두 화면
    아래로 바르게 거치)으로 2차 25Hz 보정(`CaptureConfig.
    deviceResponseByModelPrefix`)을 다시 본다. 지금 근거는 서일대 한 대뿐이다
    (5쌍 최악 수직 최대 11% · A95 7% · Jptp 5%). 개발폰(보정) ÷ 오티스폰
    (보정 없음) 비율과 정속 구간 대역별 진폭비를 같은 방법으로 낸다
    - 실기기에서 S22 의 `Build.MODEL` 이 `SM-S901` 로 시작하는지(meta.txt
      `deviceModel`, result.json `devcomp(SM-S901…,lp25.0bw2zp)`). 다르면 보정
      표 열쇠를 고친다. 현장에서 쓸 다른 기종이 있으면 그 기종도 동시 측정해
      표를 채운다 — 오티스폰과 같은 기종이면 보정 없음이 맞다
    - 표에 없는 기종으로 재면 결과 화면 · 메일에 "미보정 기종" 이 뜨는지
21. **계산 방식 차이 — 자료 필요** (2026-10-22): OTIS Lift Check 내부 표본
    속도 · 내보내기 처리, ISO 18738-1 원문 정의(P2P · A95 · 정속 구간). 오티스폰
    원시데이터를 앱 경로로 계산해도 OTIS PDF 와 수직 ±8 ~ 18% 다르고, 정속
    경계 · 가중(ISO 8041 정의대로 포함) · 반주기 정의 · A95 백분위 · Jptp 구간을
    한 가지씩 바꿔도 줄지 않았다(같은 순간끼리도 −15 ~ +11%, 기록마다 부호가
    다름). 실험 표는 `docs/experiments/otis_parity_experiment.md`. 앱 계산은 그대로 둔다
22. **정지 뒤 여유 · 출발 직후 움직임 경고 (2026-10-22)** — 정지 직후
    볼륨키로 끝내면 결과 화면에 "정지 후 1초 이상 기다린 뒤 종료하세요" 가
    뜨는지, 시작하자마자 출발하면 meta.txt `baselineSource` 가
    `startShortened` 인지. 10-22 4건은 모두 정지 뒤 1초 미만(0.27 ~ 0.98초)
    이었다. 시작 화면 · 측정 화면 · 거치 안내의 종료 안내를 "운행이 멈춘 뒤
    1초 기다렸다가 볼륨키로 끝냅니다" 로 바꿨다(2026-10-22) — 현장에서 이
    안내대로 하면 경고가 줄어드는지 본다
23. **수집 정지 때 마이크 스레드 1초 한도 (2026-10-23, `fix/cleanup-1023`)**
    — `NoiseCaptureHandler.stop()` 이 녹음 스레드를 최대 1초
    (`CAPTURE_THREAD_JOIN_LIMIT_MS`) 기다리고, 넘기면 녹음만 포기한다
    (`abandonCapture()`). Dart 응답 한도는 3.5 → 4.5초, 수집 정지 한도는
    4 → 5초로 늘렸다. Kotlin 쪽은 단위 시험이 없다
    - 평소 측정에서 `noise.m4a` 가 그대로 생기고(한도에 걸리지 않음) 측정 종료
      시간이 전과 같은지
    - 한도에 걸린 경우 Logcat 에 "noise capture thread did not stop in time"
      이 남고, 결과는 저장되며 meta.txt 에 `noiseAudioPath: null`, 메일 본문에
      "누락: noise.m4a" 가 뜨는지. 재현이 어려우면 디버그 빌드에서 녹음 스레드에
      일부러 2초 멈춤을 넣어 본다(커밋하지 않는다)
    - 포기 직후 바로 다시 측정 — 앞 스레드가 곧 풀린 경우: 소음 값 · 녹음이
      정상인지(앞 녹음기 반납 · 쓰다 만 파일 지우기를 정리 스레드가 한다), 앱
      저장 공간 맨 위에 `noise_native_*.m4a` 가 남지 않는지
    - 포기 직후 바로 다시 측정 — 앞 스레드가 끝내 풀리지 않아 앞 녹음기가
      반납되지 않은 경우: 새 녹음기를 못 열면 앱은 죽지 않고 마이크 없는
      측정이 된다(meta.txt `noiseSampleRateHz: none`, 결과 화면 · 리포트 소음
      "—" · 회색, 메일 "누락: noise.m4a"). 열리기는 하는데 소리가 안 들어오면
      소음이 모두 0(미측정)이라 같은 결과다. 기기에서 어느 쪽인지, 앱을 다시
      켜면 마이크가 돌아오는지 본다

## 알려진 미해결 (CLAUDE.md 에서 옮김, 2026-10-23)

- 신호 처리 남은 과제
  - 26.5Hz 봉우리가 개발폰에서 1.25~2.1배 크다. 40Hz 아래라 이 처리로 줄지
    않는다.
  - 차단 주파수 40Hz 는 비교 측정을 더 모아 조정할 수 있다.
  - 이 처리 전에 저장한 결과(`signalConditioning` 이 null)는 원시 256Hz
    지표라 새 결과와 기준이 다르다.
- 요구사항서(`Vibration_Checking_App_Development_20260630.pdf`)가 저장소에 없다.
- 릴리스 서명 키(2026-10-13)로 바꾸기 전 디버그 키로 서명해 깐 기기는 한
  번 지우고 새로 깔아야 한다. 기기의 측정 결과도 지워지므로 먼저 옮긴다.
- 서버 연동은 미구현이다. 로그인은 앱 안 명단으로만 판정한다(수신 이메일은
  기기에 목록으로 둔다). 엑셀의 동명이인 33쌍은 리포트(성명만)로는 구분되지
  않는다 — 결과 · 메일에는 사번이 남는다.
